# Стандарт разработки сайтов: SEO, Индексация, Скорость и Доступность

Каждый раз при разработке, доработке, сборке или аудите веб-приложений и сайтов в этом проекте ОБЯЗАТЕЛЬНО соблюдать и проверять следующие правила:

## 1. Индексация и поисковые боты (Crawling & Indexing)
- **robots.txt**:
  - Всегда доступен в корне `/robots.txt`.
  - Разрешает обход для `User-agent: *` (или явно для `Googlebot`, `YandexBot`).
  - Содержит директиву `Sitemap: https://<domain>/sitemap.xml`.
  - **Категорический запрет блокировки UTM**: НИКОГДА не писать `Disallow: /*?*utm_*`, `yclid`, `gclid` в `robots.txt`. Внешние ссылки и бэклинки приходят с UTM — блокировка краулинга запрещает Googlebot заходить на страницу, он не видит тег `<link rel="canonical">` и сжигает ссылочный вес (PageRank). Дубли параметров должны консолидироваться исключительно через Canonical.
  - Запрещает только приватные и технические пути (`/api/`, `/admin/`, `/checkout/`, приватные файлы).
- **sitemap.xml**:
  - Полный, валидный XML-файл с кодировкой UTF-8.
  - Содержит только канонические, чистые URL (без localhost, preview-доменов, хешей `#` или UTM-меток).
  - Актуальные даты `<lastmod>` и приоритеты `<priority>`.
- **Meta Robots & HTTP-заголовки**:
  - На всех целевых страницах `noindex` должен быть ВЫКЛЮЧЕН.
  - Проверять отсутствие заголовка `X-Robots-Tag: noindex` в HTTP-ответах сервера/хостинга.
- **Канонические ссылки (Canonical URL)**:
  - На каждой странице присутствует `<link rel="canonical" href="https://<domain>/path" />`.
  - Запрещены каноникалы на `localhost`, `127.0.0.1` или preview-домены (Vercel/Cloudflare Pages).
- **Навигация и ссылки**:
  - Поисковые краулеры переходят **только** по ссылкам `<a href="...">`.
  - Строго запрещено делать переходы исключительно по `onClick` на `<button>` или `<div>` без нативной ссылки.
  - Все ссылки валидны (0 битых внутренних ссылок, HTTP 200).
- **Структура URL**:
  - Единый регистр (lowercase).
  - Согласованность trailing slash (со слэшем или без него во всем проекте).
  - Редиректы только 301 (Permanent) и строго в один шаг (без redirect chains).
- **Обработка ошибок (404/410)**:
  - Несуществующие страницы должны отдавать честный HTTP статус `404 Not Found` (или `410 Gone`), а не код 200 с текстом "Страница не найдена" (Soft 404).
  - Наличие брендовой страницы 404 со ссылками на ключевые разделы и мета-тегом `robots: noindex, follow`.
- **Архитектура рендеринга (SSG / SSR vs CSR)**:
  - Не использовать hash-роутинг (`/#/page`).
  - Обеспечивать пререндеринг (SSG/SSR), чтобы в начальном HTML-ответе присутствовал текстовый контент, мета-теги и ссылки до выполнения клиентского JavaScript.
- **Быстрая индексация (IndexNow)**:
  - Отправка URL через IndexNow API для моментальной постановки в очередь обхода в Яндексе и Bing.

## 2. On-Page SEO и Семантика
- **Мета-теги**:
  - Уникальный `<title>` на каждой странице (емкий, содержит ключ и бренд).
  - Уникальный `<meta name="description">` (120–160 символов, отражает суть страницы).
- **Иерархия заголовков**:
  - Ровно один `<h1>` на странице.
  - Логичная вложенность: `<h1>` -> `<h2>` -> `<h3>` (без перескоков).
- **Изображения**:
  - Наличие информативного атрибута `alt="..."` у всех тегов `<img>`.
  - Явные атрибуты `width` и `height` (или CSS `aspect-ratio`) для предотвращения сдвига макета (CLS).
- **Язык документа и локализация**:
  - Наличие корректного атрибута языка `<html lang="ru">`.
  - Для мультиязычных сайтов — разметка `hreflang` со ссылкой `x-default`.

## 3. Микроразметка (Structured Data / JSON-LD)
- Разметка Schema.org в формате `<script type="application/ld+json">`.
- Обязательно:
  - `Organization` или `Person` с массивом `sameAs` (ссылки на GitHub, Telegram, LinkedIn, профили для E-E-A-T).
  - `BreadcrumbList` для формирования цепочки навигации в поисковой выдаче.
  - `WebSite` / `WebPage` с метаданными.
  - `FAQPage` на страницах с частыми вопросами / услугами.
  - `Service` / `Product` с ценами и условиями.
  - Валидность всех URL картинок и логотипов внутри разметки (0 битых картинок).

## 4. Социальные сети и Сниппеты (SERP & Social)
- **Open Graph**:
  - `og:type`, `og:site_name`, `og:title`, `og:description`, `og:url`, `og:image` (1200x630px, абсолютный URL).
- **Twitter Cards**:
  - `twitter:card` (summary_large_image), `twitter:title`, `twitter:description`, `twitter:image`.
- **Фавикон для поиска Google**:
  - Наличие `favicon.ico` в корне.
  - Иконки кратные 48px (48x48, 96x96, 144x144, 192x192) с `<link rel="icon">`, чтобы Google отображал иконку рядом со сниппетом в SERP.

## 5. Инфраструктура, Сеть и Безопасность
- **Cloudflare / CDN**:
  - Режим "Under Attack Mode" должен быть выключен в штатном режиме.
  - WAF / Managed Rules не должны блокировать известных ботов (Googlebot, YandexBot, Bingbot).
- **Геоблокировки (Geoblock)**:
  - Googlebot обходит сайты с IP-адресов в США. Геоблокировка не должна закрывать доступ ботам из США.
- **HTTPS & Безопасность**:
  - Принудительный редирект с HTTP на HTTPS.
  - Заголовок HSTS (`Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`).
  - Запрет на утечку sourcemaps (`.map`) и `.env` файлов в продакшене.
  - Защита системных путей `/\.(git|env|DS_Store|yml|yaml)`.

## 6. Производительность (Core Web Vitals)
- **LCP (Largest Contentful Paint < 2.5s)**:
  - Использовать `fetchpriority="high"` и `loading="eager"` (или `<link rel="preload" as="image">`) для LCP-картинки первого экрана.
  - Использовать `loading="lazy"` и `decoding="async"` для картинок ниже сгиба экрана.
- **CLS (Cumulative Layout Shift < 0.1)**:
  - Фиксация размеров картинок, баннеров и шрифтов.
- **INP (Interaction to Next Paint < 200ms)**:
  - Минимизация тяжелых синхронных задач в главном потоке JS.
- **Сжатие графики**:
  - Использование современных форматов `WebP` / `AVIF`.
- **Шрифты**:
  - `font-display: swap` для предотвращения невидимого текста (FOIT).
  - Сабсеттинг символов (только latin, cyrillic).
  - Предзагрузка ключевых шрифтов через `<link rel="preload" as="font">`.
- **Сжатие на сервере**:
  - Включение Brotli (`.br`) наряду с Gzip для текстовых ресурсов.
